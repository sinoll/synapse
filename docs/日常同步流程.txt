日常同步流程
假设你修改了项目中的 README.md 或 PHP 文件。
在项目目录打开 Git Bash，依次执行：
git add .
git commit -m "更新项目代码"
git push


这三条命令分别表示：
命令	作用
git add .	把修改、新增和删除的文件加入暂存区
git commit -m "更新项目代码"	在本地创建一个新的版本记录
git push	将本地提交同步到 GitHub
执行成功后，刷新 GitHub 仓库页面，就能看到更新后的文件。


二、如果只修改了一个文件
例如只修改了 config/web.php，可以只同步这个文件：
git add config/web.php
git commit -m "修改网站配置"
git push


这样更精确，不会把其他未打算提交的文件一起加入本次提交。
三、如果想查看哪些文件被修改
提交前可以执行：
git status

查看具体修改内容：
git diff


如果不小心执行了 git add .，也可以在提交前查看暂存区的修改：
git diff --cached





从远程仓库同步到本地

git pull origin main



1. 自动拉取并合并（最常用）

如果你本地工作区是干净的（没有未提交的改动），直接运行：
bash
git pull origin <分支名>
请谨慎使用此类代码。
• 示例： git pull origin main 或 git pull origin master
• 注意： 该命令会自动下载远程代码并直接合并（merge）到你当前的本地分支中。

2. 安全同步（先检查再合并）

如果不确定远程改动了什么，担心直接合并会引发冲突，建议使用 fetch + merge：
bash
# 1. 仅获取远程的最新修改，不影响本地代码
git fetch origin

# 2. 对比本地分支与远程分支的差异
git diff HEAD origin/<分支名>

# 3. 确认无误后，手动合并
git merge origin/<分支名>
请谨慎使用此类代码。

3. 强行覆盖本地修改（危险操作）

如果你本地的代码改乱了，完全不想要本地的修改，想彻底用远程仓库的最新代码覆盖本地，可以强制重置：
bash
# ⚠️ 注意：此操作会清空本地所有未提交的修改和干干净净的本地提交，无法找回！
git fetch --all
git reset --hard origin/<分支名>
请谨慎使用此类代码。



建一个全新的、没有历史的提交,强制覆盖远程。
用下面这个方法重来,不依赖之前的状态:

bat
:: 1. 创建全新的孤儿分支(名字随意)
git checkout --orphan clean-main

:: 2. 确认现在确实在新分支上(应显示 clean-main,且 log 报错"没有提交"是正常的)
git branch --show-current

:: 3. 清空暂存区,按 .gitignore 重新添加
git rm -r --cached . -q
git add -A

:: 4. 确认没有 mp4 / uploads
git status

:: 5. 提交
git commit -m "init"

:: 6. 现在已不在 main 上,可以删了
git branch -D main
git branch -m main

:: 7. 确认只有 1 个提交
git log --oneline

:: 8. 推送
git push origin main --force




前面几轮分支操作已经把状态搞乱了,最可靠的做法是直接重建仓库。你说过只有你一个人用,本地历史也不需要,那就这样:

bat
:: 1. 确认 .gitignore 里有 uploads 这一行
type .gitignore

:: 2. 删除旧的 git 数据,重新初始化
rmdir /s /q .git
git init -b main

:: 3. 全量添加并提交
git add -A
git status
git commit -m "init"

:: 4. 关联远程并强制推送
git remote add origin https://github.com/sinoll/synapse.git
git push -u origin main --force
