github.com同步简单手册

你已经在 GitHub 上创建好仓库了，接下来只需要把本地代码通过 Git 推送到 GitHub。你使用的是 Windows 环境，我建议直接用 Git 命令行，以后更新代码也很方便。

下面以“本地已经有一个项目文件夹，GitHub 上已经创建好一个空仓库”为例。

一、先理解同步流程
本地项目文件夹

例如：D:\project\myapp

git add → git commit → git push

GitHub 远程仓库

保存、备份和管理代码版本

首次上传通常需要设置一次远程仓库地址。以后修改代码，再执行提交和推送即可。

二、安装 Git
先检查电脑是否已经安装 Git。

在项目文件夹空白处点击右键，选择 Open Git Bash Here。

输入：

git --version

如果显示类似 git version 2.xx.x，说明已经安装。

如果提示找不到命令，去 Git for Windows 官方下载页下载安装。

Install for Windows

三、获取 GitHub 仓库地址
打开你刚创建的 GitHub 仓库页面。

你的 GitHub 仓库

点击绿色的 Code 按钮。

选择 HTTPS。

复制仓库地址。

地址格式类似：

https://github.com/你的用户名/你的仓库名.git

上面只是示例地址，请替换成你自己的真实地址。

四、首次上传本地代码
假设你的项目放在 D:\project\myapp。

打开该项目文件夹里的 Git Bash，按顺序执行下面的命令。

第 1 步：进入项目目录
如果你已经在项目目录中打开了 Git Bash，可以跳过。

cd /d/project/myapp

注意：这里是示例路径，换成你自己的项目路径。

第 2 步：初始化 Git
git init

这会在项目目录下创建 .git 隐藏目录，用来记录版本历史。不会自动上传代码。

第 3 步：设置提交者信息
如果是第一次使用 Git，需要设置：

git config --global user.name "你的GitHub用户名"
git config --global user.email "你的邮箱"

这里的邮箱建议使用 GitHub 账户绑定的邮箱，或者 GitHub 提供的隐私邮箱。

第 4 步：添加代码并提交
git add .
git commit -m "Initial commit"

含义：

git add .：将当前目录下的文件加入本次待提交内容。

git commit：在本地创建一个版本记录。

注意： 执行 git add . 前，先检查项目中是否包含密码、API Key、数据库配置、私钥等敏感文件。不要将它们上传到公开仓库。

第 5 步：关联 GitHub 仓库
将下面的地址替换成你自己的仓库地址：

git remote add origin https://github.com/sinoll/synapse.git

然后设置默认分支为 main：

git branch -M main

第 6 步：上传代码
git push -u origin main

如果弹出 GitHub 登录或授权窗口，按照提示完成授权。通常不需要把 GitHub 登录密码直接输入终端。

上传成功后，刷新 GitHub 仓库页面，就可以看到你的代码了。

五、以后修改代码，如何再次同步？
首次上传成功后，以后每次修改代码，通常只需要执行三条命令：

git add .
git commit -m "更新项目代码"
git push

例如，你修改了 Yii3 项目的控制器或新增了一个 PHP 文件，执行这些命令，就可以把新的版本推送到 GitHub。

六、两个常见问题
提示或问题

处理方式

remote origin already exists

已经配置过远程仓库，使用 git remote -v 查看地址，不要重复添加。

rejected 或 fetch first

远程仓库可能已经有 README、许可证等提交，需要先处理远程历史，不能直接强制覆盖。

Authentication failed

检查浏览器授权、账户登录状态及仓库写入权限。

上传后看不到文件

检查是否执行了 git commit 和 git push，以及当前分支是否为 main。

还有一点：如果你创建仓库时已经勾选了 Add a README file，上面首次上传的流程可能遇到远程历史冲突。这种情况最好单独处理，不要直接使用 git push --force。
